### 하지 않는 것 (Non-goals)
- 장소·가게 검색, 지도 연동 **[결정]**: 추천은 종류(장르)만 한다
- 외부 캘린더 앱(TimeBlocks, minical, iOS 캘린더) 가져오기와 동기화 **[결정]**: 일정은 앱에 직접 입력한다
- Android 지원 (지금은 하지 않음. Supabase로 바꾸면서 나중에 가능해짐)
- 커플 외 사용자 간 소셜 기능(피드, 친구, 공개 게시)
- 직접 운영하는 서버 코드 (v1~v3). Supabase가 제공하는 DB·로그인·저장소와 DB 함수만 쓴다

### 실패로 보는 것 (Anti-goals)
- 상대 일정 입력이 지금(캡처 보내고 다시 입력하기)보다 번거로우면 실패다.
- 색이 진하거나 화면이 복잡해 "커플 앱 같지 않으면" 실패다.
- 사진·일정이 커플 외의 사람에게 보일 수 있으면 실패다.

#### 2.7.1 추천 점수 규칙 **[제안]**

후보는 해당 종류(활동 또는 음식)에서 숨기지 않은 카테고리 전부다.

1. 한 명이라도 "싫어요"이면 후보에서 뺀다.
2. 점수 = 좋아요 수 × 2 (0~4)
3. 최근 6개월 데이트 기록 중 별점 4 이상인 기록에 포함되면 +1씩, 최대 +3
4. 최근 14일 안에 기록이 있으면 −3
5. 둘 다 좋아요인데 한 번도 기록이 없으면 +1 (새로운 시도)
6. 상위 5개를 점수 비례 가중치로 무작위로 하나 뽑는다(점수 0 이하는 가중치 0.5)
7. 이유 문구는 적용된 규칙에서 만든다. 예: "둘 다 좋아하고, 지난번 별점이 5개였어요"

취미·특기 태그는 v3에서 화면에 보여 주기만 하고 점수에는 쓰지 않는다. 카테고리와 연결하는 방법은 v3 이후에 정한다 **[제안]**.
